# 将来構想メモ

TAから複数の改善提案（総合プロフィール分析、適性診断、社内チャットツール連携、データ制約への対応）を受けた。これらは個別に対応するのではなく、**「データ取得のハードルを下げつつ、従業員を多面的に見る」という一つの将来ビジョンとして統合する。**

現時点でのコード実装は行わず、プレゼンの「将来構想」スライドの参考資料として、また継続開発の方向性メモとして記録する。デモでは見せず、口頭・スライド上の言及に留める。

## 1. 現状の課題

本MVPはIBM HR Analytics（海外企業の詳細な人事データ）を使用しているが、日本企業の多くはここまで精緻な人事データを保有していない。

## 2. 代替データソースの方向性

Slack等の社内チャットツールは日本企業でも導入率が高く、「新たに詳細データを集める」のではなく「既に存在するデータ（チャットログの頻度・トーン変化等）を使う」設計へ転換できる可能性がある。

## 3. 総合プロフィール分析への発展

上記データを活用し、離職リスクという単一指標だけでなく、成長曲線・強み弱み・性質特質（適性診断的な要素を含む）を可視化する。

## 4. 導入後のモデル補正（企業データによる継続的な精度向上）

現状のモデルは外部の公開データセット（IBM HR Analytics）で構築したベースモデルであり、導入企業の実態を完全には反映していない。この限界に対し、以下のフェーズで段階的に精度を高めていく構想。

- **Phase 1（導入時）**: 外部データで構築したベースモデルをそのまま提供し、まず離職リスクの傾向を可視化することから始める
- **Phase 2（運用開始〜半年〜1年）**: 企業での運用を通じて、「実際に誰が離職したか／残ったか」という結果データが蓄積される
- **Phase 3（データ蓄積後）**: 蓄積された企業独自の実データを使って、モデルを企業ごとに再学習・補正する（技術的には「ファインチューニング」と近いが、正確には企業データを加えた再学習・追加学習にあたる。専門用語の断定は避け、「企業の実データでモデルを補正していく」という説明にとどめる）

この構想により、「海外データを使っている」という初期の弱みが、運用を続けるほど自社に最適化されていくという継続利用の価値提案に転換できる。ビジネスモデル上も、継続契約の合理性を説明する材料になる。
